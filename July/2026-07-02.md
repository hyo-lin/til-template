### 새로 배운 내용
#### 주제 1: Docker Compose
- Docker Compose: 여러 컨테이너로 구성된 애플리케이션을 YAML 형식의 파일로 명확하게 정의하고, 단일 명령어로 동시에 실행 및 관리할 수 있도록 지원하는 Docker의 공식 오픈소스 도구
  - 다수의 컨테이너로 구성된 애플리케이션을 코드로 명확하게 정의하고, 한 번에 쉽게 관리하기 위해서
  - 개별 컨테이너의 이미지, 실행 명령, 환경 변수, 볼륨, 네트워크, 의존성 등을 간결하고 직관적인 YAML 형식으로 구성할 수 있게 하여 복잡한 컨테이너 환경 구성을 크게 단순화합니다.
- ### docker-compose.yml 작성
- 1. 이미지 사용 (image) 방법
  - 이미 Docker Hub에 있는 이미지를 바로 사용하는 방법입니다.
```yaml
services:
app-image:
image: your-username/docker-test-app:latest
ports:
- "8080:8080"
container_name: express-app
```
| 옵션 | 설명 |
| :--- | :--- |
| **image** | Docker Hub에서 이미 빌드된 이미지 사용 |
| **ports** | 호스트와 컨테이너의 포트 연결<br>• 앞의 `8080` = 호스트가 여는 포트<br>• 뒤의 `8080` = 컨테이너 내부 애플리케이션이 사용하는 포트 |
| **container_name** | 컨테이너 이름 지정 |

- 2. 이미지 빌드 (build) 방법  
  - Dockerfile을 이용하여 직접 이미지를 빌드해서 사용하는 방법입니다.
```yaml
services:
  app-build:
    build: .
    ports:
      - "3001:3000"
    container_name: your-container-name
```
| 옵션 | 설명 |
| :--- | :--- |
| **build** | 현재 디렉토리의 `Dockerfile`을 사용해서 이미지를 직접 빌드 |
| **ports** | 호스트와 컨테이너의 포트 연결 |
| **container_name** | 컨테이너 이름 지정 |
    
- 3. 두 가지를 혼합해 사용하는 방법
  - 일반적으로 한 가지 방식만 사용하지만, 개발용과 배포용 등으로 혼합해 사용하는 경우도 있습니다.

- ### Service: 실행해야 하는 컨테이너의 역할
```yaml
services:
  backend:
    image: my-backend:1.0.0

  mysql:
    image: mysql:8.0

  nginx:
    image: nginx:stable-alpine
```
- my-backend, mysql, nginx는 서비스의 이름
- 서비스는 컨테이너의 이름이 아니라, 애플리케이션 내부에서 사용하는 논리적인 역할 이름

- ### Network
  - compose 를 사용하면 별도로 네트워크를 만들지 않아도, 기본 네트워크자동 생성

- ### Volume
  - 컨테이너 삭제되면 ← 내부 데이터가 날아감 
  - 볼륨으로 호스트 저장소 사용할 수 있다

- ### 환경 변수
  - 환경 변수 → 컨테이너마다 다른 값을 넣는다.

- ### depend_on
```yaml
services:
  backend:
    image: my-backend:1.0.0
    depends_on:
      - mysql

  mysql:
    image: mysql:8.0
```
  - 서비스간 생성, 시작 순서, 의존성을 선언
  - 컨테이너의 생성 시작 순서를 조정할 수 있긴 한데 실제 요청 준비 순서를 보장하지는 않는다.

- ### 주의사항
  - 1. latest 태그를 피해야한다.
  - 2. depend_on 을 신뢰하지 않는다.
    - health check 를 꼭 하시는게 좋습니다.
  - 3. 로그 회전 설정
    - 서버 디스크에 계속 로그가 쌓인다.
