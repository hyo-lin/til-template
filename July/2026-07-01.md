### 새로 배운 내용
#### 주제 1: Bridge Network, Network Interface, Custom Bridge Interface
- Bridge Network: 컨테이너들이 동일한 호스트 내에서 서로 통신할 수 있도록 연결해주는 도커의 기본 가상 네트워크
  - 컨테이너 간 통신을 격리된 네트워크 환경에서 안전하고 간편하게 관리하기 위해서
  - | 구성 요소 | 설명 |
    | :--- | :--- |
    | **컨테이너 eth0** | 컨테이너 내부에 노출되는 가상 네트워크 인터페이스로, 컨테이너가 네트워크 송수신을 할 때 사용하는 엔드포인트입니다. |
    | **veth pair (가상 이더넷 쌍)** | 한쪽이 컨테이너 `eth0`와 연결되고 다른 쪽이 호스트의 `docker0` 브리지에 연결되는 가상 케이블입니다. 컨테이너 ↔ 브리지 간 실제 데이터 경로입니다. |
    | **docker0 (브리지)** | 호스트에 생성된 가상 브리지 인터페이스로, 브리지에 연결된 컨테이너들 간 트래픽을 중계하고 호스트 물리 NIC와의 게이트웨이 역할을 합니다. |
    | **호스트 eth0 (물리 NIC)** | 호스트 머신의 물리 네트워크 인터페이스로, `docker0`를 통해 외부 네트워크(인터넷, VPC 등)와 통신합니다. |
  - Host: Docker Engine 이 실행되는 실제 서버, Linux 머신
  - 네트워크 인터페이스: 네트워크 통신을 위한 출입구
- Custom Bridge Interface: 컨테이너 를 실행할 때 별도로 `—network` 옵션을 주지 않으면, 기본 bridge 할당이 된다.
  - 기본 bridge 보다 사용자 정의 bridge 더 선호한다.
  - | 비교 항목 | 기본 bridge 네트워크 | 사용자 정의 브리지 네트워크 |
    | :--- | :--- | :--- |
    | **생성 방식** | Docker 설치 시 자동 생성 | `docker network create`로 생성 |
    | **컨테이너 이름 DNS** | 기본적으로 지원하지 않음 (`--link` 필요) | **지원 (컨테이너 이름으로 바로 통신 가능)** |
    | **네트워크 분리** | 모든 기본 컨테이너가 같은 네트워크에 포함됨 | **필요한 서비스끼리만 안전하게 격리 및 묶음 가능** |
    | **실행 중 연결/해제** | 제한적 (실행 전 지정 필요) | `docker network connect`, `disconnect` 가능 |
    | **실무 권장도** | 단순 테스트 및 학습용 | **실제 서비스 단위 구성 시 강력 권장** |

#### 주제 2: Docker Network Driver
- Docker Network Driver: 도커 호스트 내에서 컨테이너를 가상의 스위치로 연결하는 네트워크 드라이버
    - Macvlan Driver: 컨테이너마다 별도의 MAC 부여 해서 컨테이너가 마치 “물리 네트워크에 직접 연결된거처럼 보이게하는 드라이버”

#### 주제 3: Host Network, Overlay Network
- Host Network: 컨테이너가 호스트의 네트워크를 직접 공유하는 방식
  - 컨테이너가 호스트의 네트워크 네임스페이스를 그대로 공유해 별도 가상 인터페이스 없이 호스트 IP를 사용
    - SSH(192.168.0.11:22)와 컨테이너 웹서비스(192.168.0.11:80)
    - 장점
      - Bridge Network 보다 네트워크 경로가 단순
      - NAT, 포트 매핑이 필요 없다.
    - 단점
      - 컨테이너랑 호스트의 네트워크 격리가 사라진다.
      - 여러 서비스가 한 서버에 공존하는 경우 일반적으로 사용하기 어렵다
- Overlay Network: 서로 다른 물리 호스트(예: 172.31.1.5, 192.168.1.25)에 있는 컨테이너들에 같은 가상 서브넷(예: 10.0.0.0/24)의 IP를 부여해 호스트 간 컨테이너 통신을 직접 가능하게 하는 가상 L2 네트워크
  - Bridge 한 대의 호스트에서 동작
  - 여러 ec2분산 된 서비스 컨테이너를 연결 할 수 있다.
  - 서비스가 다른 호스트로 이동 해도 같은 오버레이 네트워크를 쓰면 통신 가능하다.
- | 구분 | Bridge | Overlay |
  | :--- | :--- | :--- |
  | **통신 범위** | 한 대의 Docker Host | 여러 Docker Host |
  | **주 사용 환경** | Compose, 단일 EC2 | Swarm, 다중 서버 |
  | **관리 복잡도** | 낮음 | 높음 |
  | **네트워크 구성** | 로컬 가상 브리지 | 여러 호스트 위의 분산 가상망 |


### 오늘의 회고
- Bridge Network에 대해 알게되었다. 도커에서 자동으로 컨테이너가 연결되는 줄 알았는데 이번 수업을 통해 브릿지를 커스텀하여 적용해봐야겠다.
