### 새로 배운 내용
#### 주제 1: Portainer
- Portainer: Docker와 Kubernetes 같은 컨테이너 환경을 손쉽게 관리할 수 있도록 해주는 웹 기반 GUI 관리 도구
  - 여러 컨테이너 환경을 직관적인 웹 UI로 통합 관리하여 컨테이너 배포·모니터링·권한 설정 등 운영 작업을 효율화하고 관리 복잡도를 크게 줄여주기 때문에
- #### Docker Desktop vs Portainer 비교

| 구분 | Docker Desktop | Portainer |
| :--- | :--- | :--- |
| **목적** | 로컬 개발환경 구축 | 운영 환경 및 다중 서버 관리 |
| **설치 위치** | 개인 PC | 서버, 클라우드, 로컬 등 |
| **주요 대상** | 개인 개발자 | 인프라 운영팀, DevOps 팀 |
| **지원 범위** | 단일 Docker 엔진 | 다수 엔진, 스웜, 쿠버네티스 |
| **주요 기능** | 로컬 컨테이너/이미지 관리 | RBAC, 사용자 관리, 템플릿 관리, 원격 관리 |

- Portainer 볼륨: Portainer 컨테이너의 내부 데이터를 영구적으로 저장하기 위해 사용하는 Docker 볼륨
- ### Portainer 주요 구성 요소

| 구성 요소 | 역할 |
| :--- | :--- |
| **Portainer Server** | 웹 UI와 관리 기능을 제공하는 중심 서버 |
| **Docker Engine** | 실제 컨테이너·이미지·볼륨·네트워크를 실행하고 관리하는 엔진 |
| **Portainer Agent** | 원격 Docker 서버의 정보를 Portainer Server에 제공하는 에이전트 |
| **Edge Agent** | 외부에서 직접 접근하기 어려운 원격 환경을 관리할 때 사용하는 방식 |

- Docker Socket: Docker 엔진의 백그라운드 프로세스(Docker Daemon)와 통신하기 위해 사용되는 Unix 도메인 소켓(Socket) 파일
- ### Docker Socket 공유에 따른 보안 리스크
Docker 데몬은 기본적으로 `root` 권한으로 실행되므로, Docker Socket에 접근할 수 있는 Portainer는 호스트 서버에 대해 사실상 무소불위의 권한을 갖게 됩니다.

* **컨테이너 임의 조작:** 모든 컨테이너의 생성, 중지, 삭제 권한 획득
* **호스트 디렉터리 마운트:** 호스트 내부의 민감한 시스템 파일에 접근 가능
* **환경 변수 노출:** 컨테이너에 설정된 DB 패스워드, API Key 등 민감한 환경 변수 조회 가능
* **호스트 권한 탈취 위험:** Docker 엔진이 설치된 서버 전체의 제어권이 넘어갈 수 있음

- ### Portainer 운영 시 필수 보안 수칙
보안 취약점을 방지하기 위해 **Portainer 컨테이너는 절대로 외부 인터넷에 완전히 노출되어서는 안 됩니다.** 항상 네트워크 접근이 가능한 영역을 최소화(Attack Surface 축소)해야 합니다.

* **가장 안전한 인프라 구성:** `Private Subnet`에 배치하고 `VPN`을 통해서만 접근하도록 제한
* **접근 제어 (Access Control):** AWS 보안그룹(Security Group)을 활용하여 **특정 IP 대역(예: 내 PC IP)**에서만 Portainer 포트(`9000`, `9443`)로 접근을 허용

#### 주제 2: Volume
- Volume: 컨테이너 간 데이터 공유 및 영속성을 제공하기 위해 호스트 파일 시스템에 생성되는 독립적인 저장소
  - 컨테이너 종료 및 재시작에도 데이터를 영구적으로 유지하고 공유하기 위해서
- 볼륨을 사용하면 컨테이너가 삭제되거나 재시작되어도 볼륨에 저장된 데이터는 유지되며, 동일 볼륨을 여러 컨테이너에 마운트(호스트의 특정 디렉토리나 Docker 볼륨을 컨테이너 내부의 디렉토리에 연결하여, 컨테이너가 그 위치의 데이터를 그대로 사용할 수 있게 만드는 동작)하여 컨테이너 간 데이터를 공유
- ### 💾 Docker 스토리지 마운트 방식 비교
- 마운트란 특정 저장소(Volume, 디렉터리, 하드웨어 등)를 운영체제가 관리하는 파일 시스템의 특정 경로(디렉터리)에 논리적으로 연결하여 사용 가능한 상태로 만드는 프로세스이다.
| 방식 | 저장 위치 | 데이터 유지 기간 | 주 용도 및 특징 |
| :--- | :--- | :--- | :--- |
| **Volume** | 호스트 시스템의 Docker가 관리하는 독립된 저장 영역 | 컨테이너 생명주기와 상관없이 영구적 유지 | 영구적 데이터 관리 및 컨테이너 간 데이터 공유가 필요할 때 사용 |
| **Bind mount** | 호스트 시스템의 특정 디렉터리 | 호스트의 디렉터리 상태에 따라 데이터가 영구적으로 유지 | 호스트의 기존 데이터를 컨테이너에서 직접 접근하거나 호스트와 데이터를 즉각 공유하고 싶을 때 사용 |
| **tmpfs mount** | 호스트 시스템의 메모리 영역 (RAM) | 컨테이너 실행 중에만 유지되며 컨테이너 종료 시 사라짐 | 민감한 임시 데이터를 빠르게 저장하거나, 성능이 중요한 작업에서 임시 저장소로 사용 |
