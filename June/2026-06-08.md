### 새로 배운 내용
#### 주제 1: 운영체제, User mode, Kernel
- 운영체제 : 하드웨어와 소프트웨어를 관리하며, 사용자와 컴퓨터 간 상호작용을 가능하게 하는 시스템 소프트웨어
- 운영체제는 UI, System Call, Kernel로 나뉘어짐
- | 계층 | 주요 역할 | 특징 |
  | :--- | :--- | :--- |
  | **사용자 인터페이스 (UI)** | 사용자가 운영체제와 상호작용할 수 있도록 명령어 기반 또는 그래픽 기반의 인터페이스 제공. | CLI는 텍스트 명령 입력 방식, GUI는 그래픽과 마우스를 활용한 직관적 상호작용 방식 제공. |
  | **시스템 호출 (System Call)** | 응용 프로그램이 운영체제의 서비스를 요청할 수 있도록 지원하는 표준화된 인터페이스. | 운영체제 기능을 안전하고 효율적으로 사용할 수 있는 표준화된 호출점(API 역할) 제공. |
  | **커널 (Kernel)** | 하드웨어 자원을 직접 관리하며, 프로세스, 메모리, 파일 시스템, 장치 제어 등 핵심 기능을 수행. | 하드웨어와 응용 프로그램 사이에서 중재자 역할을 하며, 운영체제의 가장 기본적인 부분으로 시스템 안정성을 보장. |
- User mode: 사용자 응용 프로그램이 실행되는 환경
- Kernel mode: 운영 체제의 핵심 부분과 하드웨어가 동작하는 환경
- | 계층 (Mode) | 주요 역할 및 동작 흐름 |
  | :--- | :--- |
  | **유저 모드 (User Mode)** | 응용 프로그램이 시스템 호출(System Call)을 통해 요청을 생성하고, 커널에게 작업을 위임 |
  | **커널 모드 (Kernel Mode)** | 커널이 시스템 호출을 처리하여 하드웨어와 시스템 자원을 제어한 후 결과를 반환 |

#### 주제 2: 메모리 구조, 메모리 관리자, 메모리 관리기법, 가상 메모리
- 메모리: 데이터나 명령을 비롯하여 컴퓨터 내부에서 계산 처리 한 결과를 기억하는 장치
- 메모리 구조: 프로그램 실행을 위해 운영체제가 할당하는 메모리 공간의 체계
  - 코드(Code), 데이터(Data), 스택(Stack), 힙(Heap)
  - | 영역 | 설명 및 역할 |
    | :--- | :--- |
    | **코드 (Code)** | - 텍스트 영역이라고도 불리며, 프로그램 실행에 필요한 명령어(기계어 형태)들이 저장됨.<br>- 함수, 제어문, 상수 등이 포함되며 CPU가 명령어를 읽고 실행. |
    | **데이터 (Data)** | - 전역 변수 및 정적 변수(`static`)가 저장되는 영역.<br>- 프로그램 시작 시 메모리가 할당되고, 프로그램 종료 시 메모리가 해제됨. |
    | **힙 (Heap)** | - 동적 메모리 할당이 이루어지는 공간.<br>- 런타임 시 크기가 결정되며, 메모리를 해제하지 않을 경우 메모리 누수(Memory Leak) 발생 가능.<br>- 참조형 데이터(객체, 배열 등)가 저장됨. |
    | **스택 (Stack)** | - 함수 호출 시 생성되는 지역 변수와 매개 변수가 저장되는 임시 메모리 영역.<br>- 함수 실행이 끝나면 메모리가 자동으로 해제됨.<br>- LIFO(후입선출) 구조로 높은 주소부터 할당됨. |
- Memory Manager: 시스템 메모리를 관리하여 프로세스 간 자원 할당과 데이터 흐름을 최적화하는 소프트웨어 컴포넌트
  - | 순서 | 과정 | 설명 |
    | :---: | :--- | :--- |
    | **1** | **RAM에 공간 할당** | 메모리 관리자는 작업에 필요한 데이터를 저장하기 위해 RAM에 공간을 할당합니다.<br>이를 위해 페이지, 세그먼트와 같은 메모리 관리 단위를 사용하며, 배치 정책(First Fit, Best Fit 등)을 적용합니다. |
    | **2** | **데이터 로드** | 보조기억장치에 저장된 데이터를 RAM으로 로드하여 CPU가 접근할 수 있도록 준비합니다.<br>필요한 경우, 덜 사용되는 데이터를 보조기억장치로 스왑하여 RAM 공간을 확보합니다. |
    | **3** | **CPU로 전달** | RAM에서 데이터를 CPU로 전달하여 연산을 수행하도록 합니다.<br>CPU 캐시를 활용하면 RAM과 CPU 간 데이터 전송 속도를 최적화할 수 있습니다. |
  
  - | 작업 | 설명 |
    | :--- | :--- |
    | **가져오기** | - 보조기억장치에서 데이터를 검색하여 RAM으로 로드하는 작업입니다.<br>- 이 과정에서 메모리 관리자는 데이터를 식별하고, RAM에 복사하여 CPU가 접근할 수 있도록 준비합니다.<br>- 이 과정은 I/O 속도를 높이기 위해 버퍼링 및 캐싱 기술이 자주 활용됩니다. |
    | **배치하기** | - 로드된 데이터를 RAM 내 적절한 위치에 저장하는 작업입니다.<br>- 배치 과정에서는 First Fit, Best Fit 등의 배치 정책을 사용하여 메모리 활용도를 극대화하고 프로세스 간 충돌을 방지합니다. |
    | **재배치하기** | - RAM이 부족한 경우 덜 사용되거나 비활성화된 데이터를 보조기억장치로 옮기거나, 메모리 내 데이터를 재조정하는 작업입니다.<br>- 스왑 공간 활용, 메모리 압축 등을 통해 RAM의 여유 공간을 확보해 새로운 프로세스를 지원합니다. |

- 메모리 주소 체계: 데이터 저장 및 접근을 위한 고유 주소 체계
- 메모리 관리 기법
  - 메모리 오버레이: 제한된 메모리 환경에서 프로그램 필요한 부분만 메모리에 로드하여 실행하는 기법
  - 프로그램 전체를 RAM 메모리에 올릴 수 없는 환경에서 사용되었던 기법으로 프로그램을 여러 모듈로 나누고, 필요한 모듈만 메모리에 로드하며 실행하는 방식
  - 메모리 스왑: 메모리가 부족할 때, 데이터를 디스크로이동(Swap Out)하거나,  다시 메모리로 복구(Swap In)하는 기법
    - **스왑 인/아웃**
      - **스왑 아웃 (Swap-Out)**: 메모리에서 디스크로 데이터를 이동.
      - **스왑 인 (Swap-In)**: 디스크에서 메모리로 데이터를 다시 불러옴.
      - **페이지 인/아웃**으로 표현되기도 하며, 스왑은 프로세스 전체를 이동시키는 것과 다르게 필요한 데이터만 교체하는 방식으로도 사용됩니다.
- 메모리 분할: 컴퓨터 시스템에서 실행 중인 여러 프로세스가 물리적 메모리를 효율적으로 사용할 수 있도록 메모리를 고정 크기 또는 가변 크기의 블록으로 나누는 기법
  - | 항목 | 설명 (고정 분할 방식) |
    | :--- | :--- |
    | **분할 방식** | 메모리를 고정된 크기의 블록으로 나눠서 프로세스를 할당. |
    | **장점** | - 관리가 간단하며 메모리 할당 속도가 빠름.<br>- 프로세스 간 메모리 충돌 가능성이 낮음. |
    | **단점** | - 블록 크기와 프로세스 크기가 불일치하면 **내부 단편화(Internal Fragmentation)** 발생.<br>- 블록 크기가 다양하지 않으면 큰 프로세스는 적합한 블록을 찾지 못해 대기 발생. |
    | **적용 사례** | - 임베디드 시스템과 같은 단순한 환경.<br>- 실시간 시스템 등 메모리 할당 속도가 중요한 경우. |

  - | 항목 | 설명 (가변 분할 방식) |
    | :--- | :--- |
    | **분할 방식** | 프로세스 크기에 따라 메모리를 동적으로 분할하고 할당. |
    | **장점** | - 메모리를 효율적으로 활용하며 다양한 크기의 프로세스를 지원.<br>- 프로그램 크기에 맞춰 메모리를 유연하게 할당 가능. |
    | **단점** | - 프로세스 종료 후 빈 공간이 조각화되어 **외부 단편화(External Fragmentation)** 발생.<br>- 외부 단편화를 해결하려면 조각 모음(Compaction) 작업이 필요함. |
    | **적용 사례** | - 동적 메모리 활용이 중요한 현대 운영체제.<br>- 다양한 크기의 프로세스를 처리하는 서버 환경. |

  - | 항목 | 설명 (페이징 방식) |
    | :--- | :--- |
    | **분할 방식** | 메모리와 프로그램을 고정된 크기의 **페이지(Page)**로 나눠 관리. |
    | **장점** | - **외부 단편화가 완전히 제거**됨.<br>- 모든 페이지가 동일한 크기라 메모리 관리가 단순함. |
    | **단점** | - **내부 단편화**가 발생할 수 있음.<br>- 페이지 테이블로 인해 추가적인 메모리 오버헤드 발생.<br>- 논리 주소를 물리 주소로 변환하는 데 추가 시간이 소요됨. |
    | **적용 사례** | - 외부 단편화를 제거해야 하는 현대 운영체제.<br>- 주소 변환이 필요한 다중 프로세스 환경. |

  - | 항목 | 설명 (세그먼테이션 방식) |
    | :--- | :--- |
    | **분할 방식** | 프로그램을 논리적 단위(**코드, 데이터, 스택, 함수 등**)로 나눠서 메모리에 할당. |
    | **장점** | - 프로그램의 논리적 구조를 반영하여 직관적이고 유연함.<br>- 의미 단위로 묶여 있어 **보호(Protection)와 공유(Sharing)**가 쉬움.<br>- 큰 데이터 구조를 효율적으로 관리 가능. |
    | **단점** | - 세그먼트 크기가 가변적이므로 **외부 단편화** 발생.<br>- 각 세그먼트를 관리하는 세그먼트 테이블로 인해 추가 비용 발생. |
    | **적용 사례** | - 코드, 데이터, 스택을 명확히 분리해야 하는 응용 프로그램.<br>- 특정 대규모 데이터 구조를 관리하는 환경. |

- 가상 메모리: 실제 메모리 크기와 관계없이 프로그램이 연속된 주소 공간을 사용할 수 있도록 운영체제가 물리적 메모리를 추상화한 기술

#### 주제 3: 프로세스, 스레드, IPC, PCB
- 프로세스: 컴퓨터에서 연속적으로 실행되고 있는 컴퓨터 프로그램
- 스레드: 어떠한 프로그램 내에서, 특히 프로세스 내에서 실행되는 흐름의 단위
- | 개념 | 주요 동작 방식 및 특징 |
  | :---: | :--- |
  | **프로세스<br>(Process)** | - 동작 방식은 크게 **[로딩 ➡️ 실행 ➡️ 대기 ➡️ 종료]**의 4단계로 나뉨.<br>- 운영체제가 프로그램을 메모리에 로드하고, CPU 할당을 통해 명령어를 실행함.<br>- 입출력(I/O)이나 다른 이벤트가 발생하면 대기 상태로 진입하며, 작업 완료 시 자원을 완전히 해제하고 종료함. |
  | **스레드<br>(Thread)** | - 프로세스 내에서 생성되어 **코드(Code), 데이터(Data), 힙(Heap) 영역을 서로 공유**함.<br>- 각 스레드는 개별적인 **스택(Stack) 영역과 PC 레지스터**를 가짐.<br>- 독립적인 실행 흐름을 유지하며 하나의 프로세스 안에서 명령어를 병렬로 처리함. |

- | 단계 | 설명 | 주요 작업 |
  | :---: | :--- | :--- |
  | **로딩** | 프로그램을 메모리에 로드하여 실행 준비를 완료하는 단계 | - 프로그램의 실행 파일(코드 및 데이터)을 디스크에서 읽어 메모리에 적재<br>- 프로그램의 스택, 힙 등 실행에 필요한 메모리 구조를 초기화 |
  | **실행** | CPU가 명령어를 차례대로 처리하며 프로그램이 실행되는 단계 | - 프로그램 카운터(PC)가 가리키는 명령어를 차례로 처리<br>- 계산, 파일 입출력, 네트워크 통신 등 명령어 실행 |
  | **대기** | 외부 이벤트를 기다리며 작업이 일시 중단되는 단계 | - 파일 입출력, 네트워크 요청 등 외부 작업이 완료될 때까지 대기<br>- CPU는 대기 중인 프로그램 대신 다른 작업을 처리 |
  | **종료** | 프로그램 실행이 끝나고, 운영 체제가 자원을 해제하는 단계 | - 모든 명령어 실행이 완료되거나, 오류가 발생하면 종료<br>- 프로그램이 점유한 메모리 및 자원을 반환 |

- | 단계 | 설명 | 특징 |
  | :---: | :--- | :--- |
  | **생성** | 프로세스 실행 중 추가적인 스레드를 생성 | - 운영 체제가 스레드를 동적으로 생성<br>- 각 스레드는 고유의 실행 흐름을 가짐 |
  | **실행** | 독립적인 실행 흐름으로 각 스레드가 작업을 처리 | - 스레드는 프로세스의 자원을 공유함<br>- CPU 스케줄링에 따라 병렬적으로 실행됨 |
  | **대기** | 스레드가 동기화나 외부 이벤트를 기다리는 상태 | - 스레드 간 동기화가 필요할 경우 대기 상태 진입<br>- 파일 입출력, 네트워크 작업 등 외부 작업 완료까지 대기 |
  | **종료** | 스레드의 작업이 완료되어 자원을 반환 | - 스레드가 점유한 자원을 운영 체제가 해제함<br>- 해당 스레드만 종료되며, 프로세스 내의 다른 스레드는 영향을 받지 않음 |

- IPC: 두 개 이상의 프로세스가 데이터를 교환하고 상호작용하기 위해 사용하는 프로토콜
  - | No | IPC 방식 | 통신 매개 | 설명 |
    | :---: | :--- | :--- | :--- |
    | **1** | **Shared Memory** | 메모리 (RAM) | RAM의 특정 공간을 여러 프로세스가 공유하여 데이터를 주고받는 방식. 통신 속도가 가장 빠르지만 동기화 처리가 필수적임. |
    | **2** | **Pipe** | 파일 (커널 내부 파이프) | 단방향 통신 채널(파일)을 사용하여 한 프로세스가 데이터를 쓰고, 다른 프로세스가 이를 읽는 방식. |
    | **3** | **Socket** | 네트워크 (또는 로컬 소켓) | 네트워크 프로토콜을 통해 데이터를 주고받는 방식으로, IPC가 네트워크 영역으로 확장된 형태. |
    | **4** | **RPC** | 네트워크 / 로컬 (커널 내부) | 원격 프로시저 호출(Remote Procedure Call)로, 다른 프로세스(또는 다른 서버)에 있는 함수를 마치 로컬 함수처럼 호출하여 데이터를 교환하는 기술. |
- PCB: 운영체제가 개별 프로세스를 관리하기 위해 사용하는 (운영체제 커널의) 데이터 구조
  - | 단계 | 설명 | 주요 역할 및 기록 정보 |
    | :---: | :--- | :--- |
    | **1. 프로세스 생성** | 새 프로세스가 생성되면 운영체제가 PCB를 생성하고 초기 정보를 기록합니다. | - 프로세스 제어 블록(PCB) 생성<br>- 프로세스 ID(PID) 부여 및 초기 상태 기록 |
    | **2. 실행 상태 기록** | 프로세스 실행 중 CPU 자원 활용 상태와 다음 실행할 명령어 위치를 추적합니다. | - 프로세스 상태(Ready, Running, Blocked 등) 업데이트<br>- CPU 레지스터 값, 프로그램 카운터(PC) 실시간 기록 |
    | **3. 문맥 교환 관리** | CPU 스케줄러가 프로세스를 교체할 때 현재 작업 상태를 안전하게 보관하고 복원합니다. | - 인터럽트 발생 시 현재 프로세스 상태를 PCB에 저장<br>- 다음 실행할 프로세스의 PCB 정보를 CPU로 로드(Context Switching) |
    | **4. 자원 정보 관리** | 프로세스가 실행되면서 할당받은 다양한 시스템 자원 현황을 추적합니다. | - 할당된 메모리 범위(페이지/세그먼트 테이블 주소)<br>- 열려 있는 파일 디스크립터 목록, 입출력(I/O) 장치 정보 관리 |
    | **5. 프로세스 종료** | 프로세스가 작업을 완료하거나 오류로 종료되면 관련 자원과 관리 정보를 정리합니다. | - 프로세스가 점유하고 있던 메모리 및 자원 회수<br>- 해당 프로세스의 PCB 삭제 |
