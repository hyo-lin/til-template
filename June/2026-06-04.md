### 새로 배운 내용
#### 주제 1: filter, interceptor
- 필터: 서블릿 컨테이너가 디스패처 서블릿 요청 전달 전/후 URL 패턴에 맞는 모든 요청에 대한 부가 처리
  - 스프링 컨테이너로 요청 전달 전 서블릿 컨테이너에서 필터를 먼저 거침
- 필터 특징
  - 서블릿, 정적 컨텐츠에 대한 요청이나 응답에 필터링 작업 하는 객체
  - 서블릿 컨테이너가 제공하는 기능 (톰캣 등)
  - 스프링 프레임워크와 무관하게 작동 가능
  - 필터는 필터 체인으로 구성
- 필터 주요 용도
  - 공통 보안, 인증/인가 작업
  - 모든 요청에 대한 로깅, 감사
  - 이미지 데이터 압축 및 문자열 인코딩
  - 스프링과 분리되어야 하는 기능
- 필터 메서드
  - init()
    - 필터 객체 초기화
    - 웹 컨테이너가 1회 호출함
  - doFilter()
    - URL 패턴에 맞는 모든 요청이 디스패처 서블릿에 전달되기 전 실행 
    - 파라미터에 FilterChain 이 있음.
    - 필터 체인에 doFilter 로 다음 대상으로 요청 전달
  - destory()
    - 필터 객체를 서비스에서 제거
    - 필터에서 사용했던 자원을 반환하는 등 동작 정의
    - 웹 컨테이너에 의해 1번 호출, 더 이상 doFilter 에 의해 처리 X
- 필터 체인
  - 서블릿 컨테이너가 관리하는 필터들의 연결고리
  - 디스패처 서블릿 도착 전, 필요한 여러 필터를 순차적으로 거치도록 필터 등록 순서에 따라 순차 처리 순서 설정
  - 각 필터에서 doFilter() 호출로 다음 필터 호출
- 서블릿 컨테이너에서의 필터
  - 서블릿 컨테이너는 스프링 내부 영역이 아님, 필터에서도 DI 같은 스프링 기술이 필요
  - DelegatingFilterProxy: 서블릿 컨테이너에서 관리되는 프록시용 필터
    - 요청이 오면 우리가 만든 필터 에게 요청 위임
- 인터셉터: 디스패처 서블릿이 컨트롤러 호출 전/후 호출되는 기능
- 인터셉터 특징
  - 프링이 제공하는 기술
  - 요청과 응답을 참조, 가공하는 기능
  - 스프링 컨텍스트에서 동작 제공
- 인터셉터 주요 용도
  - 부적인 보안, 인증/인가 작업
  - API 호출에 대한 로깅 또는 감사
  - 컨트롤러로 넘겨주는 정보 가공
- 인터셉트 메서드
  - preHandle()
    - 컨트롤러 호출 전 실행
    - 요청 정보를 가공, 추가하는 경우 반환 타입은 boolean | true: 다음 인터셉터 혹은 컨트롤러 | false: 작업 중지
  - postHandle()
    - 컨트롤러 호출 후 실행
    - 컨트롤러 반환 값 타입 정보 제공
    - 컨트롤러 하위에서 예외 발생 시 호출되지 않음
  - afterCompletion()
    - 모든 작업이 완료된 후 실행
    - 요청 처리 중 사용한 리소스 반환 등
    - 요청 중, 예외 발생 되더라도 반드시 afterCompletion 은 호출
- | 구분 | 필터 (Filter) | 인터셉터 (Interceptor) |
  | :--- | :--- | :--- |
  | **관리 컨테이너** | 서블릿 컨테이너 | 스프링 컨테이너 |
  | **스프링 예외** | X | O |
  | **Req, Res 객체 조작** | O | X |
  | **용도** | • 공통 보안 및 인증/인가<br>• 모든 요청에 대한 로깅 및 감사<br>• 이미지, 데이터 압축 및 인코딩 | • 세부적인 보안 및 인증/인가<br>• API 호출에 대한 로깅 및 감사<br>• 컨트롤러로 넘겨주는 정보의 가공 |

#### 주제 2: ExceptionHandler, RestControllerAdvice, ResponseStatus
- 자바에서 예외 처리 방식
  - try catch
    - 중복되는 코드
    - 가독성 저하
    - 유지보수 어려움
    - 예외 처리 흐름 불명확
  - BasicErrorController
    - 에러 처리라는 공통 관심사
    - 예외 발생 시, 위 컨트롤러를 호출
    - 에러 요청을 다시 WAS 에 전달
    - 별도 설정 없으면 여기에서 에러 처리
- 스프링이 제공하는 예외 처리 방법들
- @ResponseStatus: 에러 HTTP 상태를 변경하는 어노테이션
  - 응답은 BasicErrorController 에 의해 만들어짐
  - 에러 응답 내용 수정하기가 힘듬
  - 예외 클래스랑 강하게 결합
  - 외부에서 정의한 Exception 클래스에서 X
- @ExceptionHandler
  - 매우 유연하게 에러 처리 가능
  - Exception 클래스를 속성으로 받아 처리할 예외를 지정함
  - @ResponseStatus 와 결합 가능
  - 에러 응답을 자유롭게 다룰 수 있음
- @ControllerAdvice @RestControllerAdvice
  - 스프링 전역으로 @ExceptionHandler 적용하도록 자바 빈으로 등록되어 전역에서 사용 가능
  - 두 개의 차이는 @ResponseBody 여부 -> 응답을 JSON 으로 파싱
  - 여러 컨트롤러에서 ExceptionHandler 적용 가능
  - 장점
    - 하나의 클래스로 모든 컨트롤러 전역 예외 처리
    - 직접 정의한 에러 응답을 일관성 있게 전달
    - 별도의 try-catch 없이 코드 가독성 높음
  -주의
    - 프로젝트당 하나의 ControllerAdvice 관리
    - 직접 구현한 Exception 클래스는 한 곳에서 관리
    
#### 주제 3: 파일처리
- ImageProcessor: 공통으로 사용할 이미지 처리(압축하기, 파일 포맷 변환하기)
- FileService: 파일 서비스가 제공해야하는 기능 명세
- LocalFileService:
  - FileService 인터페이스 구현체
  - MultipartFile 로 파일 전달 받음
  - 로컬에 파일 저장하는 기능 제공
- ImageService: 
  - 이미지 업로드 비즈니스 로직을 처리하는 서비스 코드
  - 전달된 멀티파트 압축하고 저장하는 비즈니스 로직 진행
