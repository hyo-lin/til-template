### 새로 배운 내용
#### 주제 1: 교착상태, 기아상태
- 교착상태: 두 개 이상의 프로세스나 쓰레드가 자원을 점유한 채 서로가 필요로 하는 자원을 기다리며 무한히 대기하는 상태
  - | 조건 | 설명 |
    | :--- | :--- |
    | **상호 배제**<br>*(Mutual Exclusion)* | 자원은 한 번에 하나의 프로세스/스레드만 사용할 수 있어야 합니다. (독점적 사용) |
    | **점유와 대기**<br>*(Hold and Wait)* | 최소한 하나의 자원을 점유(Hold)한 상태에서, 다른 프로세스가 사용 중인 추가 자원을 얻기 위해 대기(Wait)하는 프로세스가 존재해야 합니다. |
    | **비선점**<br>*(No Preemption)* | 다른 프로세스가 이미 선점하여 사용하고 있는 자원은 강제로 빼앗을 수 없고, 사용이 끝날 때까지 기다려야 합니다. |
    | **순환 대기**<br>*(Circular Wait)* | 대기 중인 프로세스들이 자원을 서로 기다리면서, 마지막 프로세스가 첫 번째 프로세스의 자원을 기다리는 형태의 **순환 구조(상호 대기 상태)**를 형성해야 합니다. |
- 기아상태 (Starvation): 기아 상태(Starvation)는 운영 체제에서 특정 프로세스나 스레드가 자원을 장시간 할당받지 못하여 실행되지 못하는 상태를 의미함.
  - 실행 준비 큐(Ready Queue)에서 우선순위 기반 스케줄링이 정상적으로 이루어지지 않아 특정 스레드가 계속해서 우선순위에 밀려 CPU를 할당받지 못함.
  - 해결방법
    - 1. 에이징: 오래 기다린 작업의 우선순위를 점진적으로 높이는 방식
    - 2. 라운드 로빈: 모든 작업한테 일정한 시간 조각
    - 3. 최대 대기 시간 설정: 일정 시간 이상 기다린 작업은 강제로 실행 기회를 부여
    - 4. 공정한 큐 사용하기
      - FIFO 큐, Fair Lock, Fair Lock
- 데드락(Deadlock) vs 기아 상태(Starvation) 비교
  - | 구분 | 데드락 (Deadlock, 교착 상태) | 기아 상태 (Starvation) |
    | :--- | :--- | :--- |
    | **정의** | 둘 이상의 프로세스가 서로 상대가 점유한 자원을 기다려, 무한 대기에 빠지는 상황 | 하나의 프로세스(또는 일부 프로세스)가 자원을 얻지 못하고 계속해서 대기하는 상태 |
    | **발생 원인** | 상호배제 · 점유대기 · 비선점 · 환형대기 (4가지 조건)가 동시에 충족 | 우선순위 스케줄링 등에서 낮은 우선순위 작업이 고우선순위 작업에 계속 밀려 CPU나 자원을 할당받지 못하는 경우 등 |
    | **특징** | 프로세스들이 서로 자원을 대기하므로, 전체 시스템이 멈춰버리는 형태 | 프로세스가 일방적으로 자원을 못 받고, 다른 프로세스는 계속 자원 사용 <br>→ 한쪽만 무한 대기에 빠짐 |
    | **결과** | 모든 관련 프로세스가 진행 불가 상태로 멈춰, 공동 교착 | 특정 프로세스(또는 스레드)만 영원히 자원 할당 기회를 얻지 못해 작업 완료가 불가능 |
    | **대표 해결 기법**| 자원할당 순서 준수 · 은행가 알고리즘 · 타임아웃<br>(Deadlock Prevention / Detection / Recovery) | 우선순위 올리기(Aging), 타임 슬라이스 보장<br>→ 모든 프로세스가 일정 시간 안에 자원 할당받도록 스케줄링 |

#### 주제 2: 세마포어
- 세마포어: 공유자원에 접근할 수 있는 "허가권(Permit)"의 개수를 관리하는 동기화 방법
  - 세마포어(Semaphore) 연산 구조
    - | 명칭 | 연산 이름 | 설명 |
      | :--- | :--- | :--- |
      | **세마포어 S** | - | * **정의:** 현재 공유 자원에 접근할 수 있는 자원의 수를 나타내며, 자원의 사용 및 해제에 따라 값이 동적으로 변함.<br>* **특징:** 세마포어 값 $S$는 자원 사용 가능 수를 추적하며, 각 $P(\text{wait})$와 $V(\text{signal})$ 연산에 따라 증가 또는 감소. |
      | **P** | `wait()` | * **역할:** 세마포어 값을 감소시키며, 공유 자원을 사용할 수 있는 권한을 감소시킴.<br>* **동작 메커니즘:**<br>&nbsp;&nbsp;1. 세마포어 값 $S$가 0보다 크면 자원 접근 허용 후 값을 1 감소.<br>&nbsp;&nbsp;2. 세마포어 값 $S$가 0이면, 자원이 모두 사용 중이므로 프로세스/스레드는 대기 상태로 전환. |
      | **V** | `signal()` | * **역할:** 세마포어 값을 증가시키며, 공유 자원을 사용할 수 있는 권한을 증가시킴.<br>* **동작 메커니즘:**<br>&nbsp;&nbsp;1. 자원을 사용한 프로세스/스레드가 작업 완료 후, 세마포어 값을 1 증가.<br>&nbsp;&nbsp;2. 대기 중인 프로세스/스레드가 있으면, 세마포어 값 증가로 접근 권한 부여. |
  - 이진 세마포어(Binary) vs 카운팅 세마포어(Counting) 비교
    - | 구분 | 이진 세마포어 (Binary Semaphore) | 카운팅 세마포어 (Counting Semaphore) |
      | :--- | :--- | :--- |
      | **정의** | 값이 0 또는 1로만 동작하며, **단일 자원**에 대한 접근을 제어 | 값이 0 이상의 정수로 동작하며, **다중 자원**에 대한 접근을 제어 |
      | **값의 범위** | `0`과 `1` | `0` 이상의 정수 ($\ge 0$) |
      | **사용 목적** | 단일 자원 보호 (예: 특정 파일 접근, 단일 리소스 제어) | 다중 자원 보호 (예: 데이터베이스 연결 풀, 네트워크 포트 관리) |
      | **특징** | * 뮤텍스(Mutex)와 유사하지만 소유권 개념이 없음.<br>* 자원이 사용 중(0)이면 다른 스레드/프로세스는 무조건 대기. | * 사용 가능한 자원의 총개수를 카운트하여 관리.<br>* 자원이 부족하면 대기 큐(Queue)에 요청이 저장됨. |
      | **예시** | 단일 파일 쓰기 작업, 단일 디바이스 제어 | 데이터베이스 커넥션 풀(Connection Pool), 병렬 처리에서의 최대 작업 수 제한 |
  
  - Thread들이 공유 자원을 점유하기 위해 세마포어에 P(wait) 연산을 요청하며, 자원 사용 후 V(signal) 연산으로 점유를 해제합니다.
  - 알아야 하는 이유
    - 효율적인 자원 관리
    - 병렬 처리 제어
    - 상황에 맞는 도구 선택(다중 프로듀서-컨슈머 문제, 네트워크 연결 관리, 리소스 풀이 필요한 환경에서 자주 사용)

#### 주제 3: 리눅스 명령어
- Linux: Unix 기반의 오픈소스 운영체제 커널
- 안정적이고 확장성이 높으며, 오픈소스 기반으로 자유롭게 수정·배포할 수 있는 운영 환경을 제공하기 때문에
- | 명령어 | 역할 | 예시 |
  | :--- | :--- | :--- |
  | **`ps`** | 현재 실행 중인 프로세스 상태 스냅샷 확인 | `ps aux` 또는 `ps -ef` |
  | **`whois`** | 도메인의 정보(등록기관, 소유자, 만료일 등) 조회 | `whois gabia.com` |
  | **`nslookup`** | 도메인에 매핑된 IP 주소 조회 | `nslookup gabia.com` |
  | **`ssh`** | 보안 셸을 이용한 원격 리눅스 서버 터미널 접속 | `ssh id@domain.com` |
  | **`pwd`** | 현재 작업 중인 디렉터리의 절대 경로 위치 확인 | `pwd` |
  | **`ls`** | 현재 위치한 디렉터리 내의 파일 및 폴더 목록 확인 | `ls -al` |
  | **`cd`** | 원하는 디렉터리(폴더) 위치로 이동 | `cd /var/log` |
  | **`mkdir`** | 새로운 디렉터리(폴더) 생성 | `mkdir logs` |
  | **`touch`** | 내용이 비어 있는 새로운 파일 생성 | `touch app.log` |
  | **`cp`** | 파일 또는 디렉터리를 복사 | `cp app.log app-backup.log` |
  | **`mv`** | 파일의 위치를 이동하거나 이름을 변경 | `mv old.log new.log` |
  | **`rm`** | 파일 또는 디렉터리를 삭제 | `rm app.log` |
  | **`cat`** | 파일의 전체 내용을 터미널 창에 한 번에 출력 | `cat app.log` |
  | **`less`** | 양이 많은 긴 파일을 화면 단위(페이지)로 나누어 보기 | `less app.log` |

- Crontab: 리눅스에서 특정 명령어나 스크립트를 정해진 일정에 자동으로 실행하도록 예약하는 명령어
- | 구분 | 기능 | 기호 | 예시 |
  | :--- | :--- | :---: | :--- |
  | **파이프 (Pipe)** | 한 명령어의 출력 결과를 다음 명령어의 입력으로 전달합니다. | `\|` | `ls -l \| grep txt` <br>*(목록 중 txt가 포함된 파일만 필터링)* |
  | **리다이렉션 (덮어쓰기)** | 명령어의 출력 결과를 파일로 저장합니다. (기존 내용 삭제 후 새로 작성) | `>` | `ls > list.txt` <br>*(목록을 list.txt 파일에 저장)* |
  | **리다이렉션 (이어쓰기)** | 명령어의 출력 결과를 파일 끝에 덧붙여 저장합니다. (기존 내용 보존) | `>>` | `echo "끝" >> list.txt` <br>*(기존 내용 뒤에 문자열 추가)* |
- | 명령어 | 역할 | 실무 예시 |
  | :--- | :--- | :--- |
  | **`top`** | 실시간 시스템 프로세스 및 자원 사용량 모니터링 | `top` |
  | **`ps`** | 현재 실행 중인 프로세스 목록 출력 | `ps aux \| grep spring` |
  | **`ss`** | 네트워크 소켓 및 포트 점유 상태 확인 | `ss -tulnp \| grep 8080` |
- | 명령어 | 핵심 목적 | 설명 |
  | :--- | :--- | :--- |
  | **`df`** | **"디스크 몇 % 찼지?"** | 파일 시스템의 전체 용량 및 남은 용량 확인 (`df -h`) |
  | **`du`** | **"누가 용량 다 쓰지?"** | 특정 디렉터리 및 파일이 차지하는 용량 확인 (`du -sh *`) |
- `dig`: DNS 네임서버에 질의하여 도메인 매핑 상태를 확인하는 명령어
- | 조회 레코드 | 확인하는 상황 |
  | :--- | :--- |
  | **`A / AAAA`** | 도메인이 서버 IP를 올바르게 바라보고 있는지 확인할 때 |
  | **`CNAME`** | AWS 로드밸런서(ALB)나 CDN 서비스에 잘 연결되었는지 확인할 때 |
  | **`TXT`** | 도메인 소유권 인증이 필요할 때 |
  | **`MX / SPF`** | 메일 발송 도메인 설정 검증 (스팸 분류 방지) |
