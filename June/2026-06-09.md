### 새로 배운 내용
#### 주제 1: 동시성
- 동시성: 동시성은 하나의 CPU에서 여러 작업(프로세스 또는 스레드)이 동시에 실행되는 것처럼 보이게 하는 개념입니다.
  - 작업방식: 작업을 작은 단위로 나누어 짧은 실행 시간을 할당하고, 스케줄러가 이를 관리하며 작업 간 전환(컨텍스트 스위칭)을 수행합니다.
  - | 단계 | 설명 |
    | :--- | :--- |
    | **1. 작업 분할** | 실행해야 할 작업을 작은 단위로 나눕니다. |
    | **2. 시간 할당** | 각 작업에 짧은 실행 시간을 할당하여 순차적으로 실행합니다. |
    | **3. 컨텍스트 스위칭** | 작업 간 전환 시 필요한 상태를 저장하고 복원하여 작업이 중단 없이 진행되도록 합니다. |

#### 주제 2: 스케줄러, 스케줄링
- 스케줄러: 스케줄러는 운영체제의 핵심 구성 요소로, CPU와 같은 시스템 자원을 적절히 분배하기 위해 프로세스나 스레드의 실행 순서를 관리하는 역할
  - 스케줄러의 주요 기능
  - 1. **작업 선택**
      - 실행 가능한 작업(프로세스 또는 스레드) 중에서 **어떤 작업을 실행할지 결정**합니다.
      - 예: 대기 중인 작업들 중 우선순위가 높은 작업을 선택.
  - 2. **자원 분배**
      - CPU와 같은 제한된 자원을 여러 작업이 **공평하게 사용할 수 있도록 분배**합니다.
      - 각 작업에 짧은 시간(타임 슬라이스)을 할당하고 순환적으로 실행.
  - 3. **컨텍스트 스위칭 관리**
      - 작업 간 전환 시, 이전 작업의 상태(레지스터, 프로그램 카운터 등)를 저장하고, 새로운 작업의 상태를 복원하여 작업이 중단 없이 진행되도록 합니다.
  - | 스케줄러 종류 | 역할 | 설명 |
    | :--- | :--- | :--- |
    | **장기 스케줄러**<br>*(Long-term Scheduler)* | 시스템에 얼마나 많은 작업을 실행할지 결정 | 디스크에서 메모리로 로드할 작업을 선택하며, 시스템의 전체적인 작업 부하(Degree of Multiprogramming)를 조절합니다. |
    | **중기 스케줄러**<br>*(Medium-term Scheduler)* | 메모리에 있는 작업 중 어떤 작업을 임시로 중단(스왑)할지 결정 | 메모리가 부족할 경우 비활성 작업을 디스크(Swap-out)로 이동시켜 자원을 확보하고 메모리 혼잡도를 완화합니다. |
    | **단기 스케줄러**<br>*(Short-term Scheduler)* | 실행 가능한 작업 중 다음에 CPU를 사용할 작업을 결정 | 준비 큐(Ready Queue)에 있는 작업 중 CPU를 점유할 프로세스를 선택하여 빠르게 전환(Context Switching)합니다. |

  - CPU 스케줄러의 목적 및 사용 이유
  - | 목적 | 설명 |
    | :--- | :--- |
    | **CPU 이용률 최대화**<br>*(CPU Utilization)* | CPU를 가능한 한 쉬지 않고 자주 사용하여 시스템의 전반적인 성능과 효율을 극대화합니다. |
    | **처리량 최대화**<br>*(Throughput)* | 단위 시간 동안 완료 및 처리 가능한 작업(프로세스)의 수를 늘려 시스템 처리량을 최적화합니다. |

- 스케줄링: CPU와 같은 자원을 프로세스와 스레드들이 사용할 수 있도록 줄을 세우는 과정
  - 스케줄링 레벨 및 역할
  - | 스케줄링 레벨 | 역할 | 설명 |
    | :--- | :--- | :--- |
    | **고수준 스케줄링**<br>*(High-level Scheduling)* | 장기적이고 시스템 전체의 부하 관리 | 시스템이 처리할 프로세스 수를 결정(장기 스케줄러의 역할)하고, 시스템의 전반적인 부하를 조절합니다. |
    | **중간 수준 스케줄링**<br>*(Middle-level Scheduling)* | 장기적이고 시스템 전체의 부하 관리 | 시스템 자원을 효율적으로 활용하기 위해 일부 프로세스를 대기 상태나 휴면 상태로 전환(중기 스케줄러의 역할)하여 메모리를 조절합니다. |
    | **저수준 스케줄링**<br>*(Low-level Scheduling)* | 단기적이고 미시적인 결정 (CPU 단위 관리) | 준비 큐에 있는 프로세스 중 어떤 프로세스에게 CPU 자원을 할당할지 결정(단기 스케줄러의 역할)합니다. |
  - 사용방법
  - 1. 스케줄링 정책 설정
  - 2. 스케줄링 알고리즘 적용
    - | 알고리즘 | 설명 | 특징 |
      | :--- | :--- | :--- |
      | **FCFS**<br>*(First-Come, First-Served)* | 프로세스가 도착한 순서대로 CPU를 할당하여 처리합니다. | • 구현이 매우 단순하고 직관적입니다.<br>• 앞의 긴 작업으로 인해 뒤의 짧은 작업들이 오래 대기하는 **호위 효과(Convoy Effect)**가 발생할 수 있어 평균 대기 시간이 길어질 수 있습니다. |
      | **Round Robin** | 각 프로세스에 동일한 일정 시간(**Time Slice / Time Quantum**)을 할당하여 순차적으로 실행합니다. | • 모든 프로세스가 공정하게 CPU를 공유합니다.<br>• 시분할 시스템에 적합하며, 할당량이 너무 크면 FCFS와 같아지고 너무 작으면 **컨텍스트 스위칭 오버헤드**가 커집니다. |
      | **Priority Scheduling** | 프로세스마다 우선순위를 부여하고, 가장 높은 우선순위를 가진 작업부터 처리합니다. | • 중요도가 높은 작업을 빠르게 처리할 수 있습니다.<br>• 우선순위가 낮은 작업은 계속 밀리는 **기아 상태(Starvation)**가 발생할 수 있으며, 이를 해결하기 위해 오래 대기한 작업의 우선순위를 높이는 **에이징(Aging)** 기법이 필요합니다. |
      | **SJF**<br>*(Shortest Job First)* | 실행(Burst) 시간이 가장 짧은 작업부터 우선적으로 처리합니다. | • 최적의 **평균 대기 시간(Average Waiting Time)**을 보장합니다.<br>• 실행 시간이 긴 작업은 뒤로 밀려 기아 상태가 발생할 수 있으며, 실제 환경에서는 프로세스의 CPU 실행 시간을 정확히 예측하기 어렵습니다. |
  - 3. 선점형 및 비선점형 선택
    - 선점형: 운영체제가 CPU 자원을 강제로 회수해 다른 프로세스에 할당 가능.
    - 비선점형: 프로세스가 스스로 자원을 해제하기 전까지 다른 프로세스가 자원을 빼앗지 않음.
  - 4. 멀티레벨 큐 스케줄링
    - | 항목 | 설명 |
      | :--- | :--- |
      | **그룹화 기준** | 프로세스의 특성에 따라 **CPU 집약형 작업**(배치 처리 등)과 **I/O 중심 작업**(인터랙티브 작업 등)으로 명확히 구분하여 서로 다른 큐에 배정합니다. |
      | **정책 적용** | 각 큐마다 독립적인 스케줄링 알고리즘을 적용합니다. (예: 응답성이 중요한 상위 우선순위 그룹에는 **Round Robin**, 일괄 처리가 중요한 하위 그룹에는 **FCFS** 적용) |
      | **장점** | 서로 다른 작업 특성에 맞는 최적의 스케줄링 정책을 적용할 수 있어, 시스템 전체의 **자원 활용 효율성**을 높이고 작업 성격에 맞는 **공정성**을 보장합니다. |
  - 5. 시뮬레이션 및 테스트

#### 주제 3: 병렬성, Job Queue, Ready Queue
- 병렬성: 여러 CPU 코어 또는 다중 프로세서를 사용하여 여러 작업을 물리적으로 동시에 실행하는 개념
- 병렬성은 동시성(Concurrency)과 달리 작업이 실제로 동시에 실행되며, 이를 위해 하드웨어 지원이 필수적입니다.
  - 병렬 처리(Parallel Processing) 단계 및 프로세스
  - | 단계 | 설명 |
    | :--- | :--- |
    | **1. 작업 분할** | 실행할 작업을 서로 간섭이 없는 독립적인 단위로 잘게 나눕니다. |
    | **2. 자원 할당** | 분할된 각 작업에 대해 현재 사용 가능한 CPU 코어, 메모리 등 하드웨어 자원을 최적화하여 할당합니다. |
    | **3. 병렬 실행** | 할당된 자원을 바탕으로 각 작업이 여러 코어에서 독립적으로 동시에(Concurrently & Parallelly) 실행됩니다. |
    | **4. 결과 통합** | 동시에 실행되었던 각 작업의 개별 결과물들을 하나로 취합하고 결합하여 사용자에게 최종적으로 전달합니다. |
    | **5. 오류 복구 및 관리** | 병렬 처리 도중 특정 작업에서 오류가 발생하면, 해당 작업을 재시도(Retry)하거나 예외 처리를 통해 전체 프로세스가 중단 없이 계속 진행되도록 보장합니다. |

- 동시성(Concurrency) vs 병렬성(Parallelism) 비교
- | 구분 | 동시성 (Concurrency) | 병렬성 (Parallelism) |
  | :--- | :--- | :--- |
  | **정의** | 하나의 CPU(싱글 코어)에서 여러 작업을 아주 빠르게 전환하며 실행하는 방식입니다. | 여러 CPU(멀티 코어)에서 여러 작업을 물리적으로 동시에 실행하는 방식입니다. |
  | **작업 방식** | **CPU 스케줄링(시분할)**을 통해 작업을 번갈아 가며 실행하여, 마치 동시에 실행되는 것처럼 보이게 합니다. | 작업을 완전히 분리하여 **다중 코어(Multi-core)**에서 실제로 독립된 연산이 동시에 처리됩니다. |
  | **적용 사례** | 대기 시간이 많은 **I/O 작업 중심 프로그램** (웹 서버, 네트워크 통신 등) | 연산량이 많은 **계산 작업 중심 프로그램** (머신러닝 학습, 그래픽 렌더링, 시뮬레이션 등) |
  | **의존성** | 싱글 코어에서도 작동하므로 하드웨어 환경과 무관하게 논리적 구조로 구현 가능합니다. | CPU 멀티 코어 및 병렬 처리를 지원하는 **하드웨어 아키텍처가 반드시 필요**합니다. |

#### 스케줄링 레벨과 대기 큐의 흐름

* **⚙️ STEP 1 : 고수준 스케줄링 (High-Level)**
    * **관리 대상 :** 작업 대기 큐 (`Job Queue` / 디스크 위치)
    * **주요 역할 :** 사용자가 프로그램을 실행했을 때, 디스크에서 대기 중인 작업 중 **어떤 것을 메모리에 올릴지(승인)** 결정합니다. 시스템 전체의 프로세스 수를 조절하는 거시적인 단계입니다.
      <br>
* **🔄 중간 과정 :** 메모리 할당 및 프로세스 생성
  <br>
* **⚙️ STEP 2 : 저수준 스케줄링 (Low-Level)**
    * **관리 대상 :** 실행 대기 큐 (`Ready Queue` / 메모리 위치)
    * **주요 역할 :** 메모리에 올라와 준비가 완료된 프로세스 중 **지금 당장 어떤 것에 CPU를 할당할지** 결정합니다. 밀리초 단위로 빠르게 실행 자원을 분배하는 미시적인 단계입니다.
      <br>
* **🚀 최종 단계 :** CPU 디스패치 및 실행 (`Running`)
