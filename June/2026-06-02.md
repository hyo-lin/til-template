### 새로 배운 내용
#### 주제 1: 값 타입과 임배디드 매핑
- 기본값 타입: 단일 값(예: 이름, 나이, 금액)으로만 의미를 가지는 데이터를 엔티티의 필드로 직접 정의해 테이블 컬럼에 저장하는 방식
  - 식별자나 연관관계가 필요 없는 단순한 값을 엔티티 내부에서 직접 다루어 설계를 단순화하고, 데이터베이스와 매핑하기 위해서
- 임베디드 타입: 두 개 이상의 값을 하나의 객체로 묶어 엔티티에 포함시켜 사용하는, 재사용 가능한 값 타입
  - 작성자 정보, 생성 일시처럼 의미 있는 값들의 묶음을 각각 하나의 객체로 만들어 반복을 줄이고 설계를 일관되게 유지하기 위해서
  - 값을 묶은 클래스를 @Embeddable로 선언하고, 이 클래스를 포함할 엔티티 필드에 @Embedded를 붙임
- 컬렉션 값 타입: 엔티티에 직접 연관되지 않는 여러 개의 값(예: 태그 목록, 주소 이력 등)을 리스트나 세트 형태로 저장하기 위한 값 타입
  - 여러 개의 단순 값을 엔티티 없이 테이블에 분리 저장하면서도 부모 객체와 함께 일괄적으로 관리하기 위해서
  - @ElementCollection을 필드에 선언하고, 값 타입 클래스를 @Embeddable로 정의하여 리스트나 세트 형태로 매핑
#### 주제 2: Spring Data JPA
- Spring Data JPA: JPA 기반의 데이터 처리를 자동화해 인터페이스만으로 리포지토리를 쉽게 구현할 수 있도록 도와주는 Spring 모듈
  - 반복적인 CRUD 코드 없이 인터페이스만으로 리포지토리를 구현해 개발 생산성과 유지보수 효율을 높이기 위해서
  - Spring Data JPA를 사용하면, 순수 JPA만 사용할 때처럼 EntityManager로 매번 persist(), find(), merge() 같은 CRUD 메서드를 직접 작성할 필요가 없음
- Query Method: 리포지토리 인터페이스의 메서드 이름을 기반으로 JPQL 쿼리를 자동으로 생성해주는 기능
- @Query: 리포지토리 메서드에 JPQL이나 SQL 쿼리를 직접 작성해 실행할 수 있도록 해주는 어노테이션
- @EntityGraph: 특정 엔티티를 조회할 때 함께 로딩할 연관 엔티티를 사전에 지정하여, N+1 문제를 해결할 수 있게 해주는 어노테이션
- Pagable: 페이징 처리를 위해 페이지 번호, 크기, 정렬 정보를 전달하는 객체
#### 주제 3: JPQL, queryDSL
- JPQL: 엔티티 객체를 대상으로 데이터를 조회하거나 조작할 수 있도록 제공되는 객체지향 쿼리 언어
  - 엔티티를 기준으로 쿼리를 작성해 객체 지향 설계를 유지하면서, 데이터베이스에 독립적이고 유지보수하기 쉬운 코드를 작성할 수 있기 때문에
  - EntityManager의 createQuery() 메서드에 엔티티 기준의 쿼리 문자열을 작성하고, 실행하여 결과를 조회
  - JPQL은 특정 데이터베이스 문법에 종속되지 않음
- fetch join: 지연 로딩된 연관 엔티티를 한 번의 쿼리로 함께 조회하기 위해 사용하는 조인 방식
1. N+1은 “처음에는 주 엔티티만 조회, 연관 데이터는 나중에 하나씩 조회”하는 방식 때문에 발생합니다.
2. fetch join은 “처음부터 주 엔티티와 연관 데이터를 한 쿼리로 모두 조회”하여, 이후 탐색 시 추가 쿼리가 필요 없게 만듭니다.
3. 이렇게 객체 그래프가 한 번에 완성되므로, N개의 추가 쿼리가 사라지고 조회 효율이 크게 향상됩니다.
- Projection: 엔티티 전체가 아닌 필요한 필드만 선택해 조회할 수 있도록 지원하는 데이터 조회 방식
- QueryDSL: 자바 코드로 JPQL이나 SQL 같은 쿼리를 직접 작성하지 않고, 메서드 호출과 객체 지향 문법을 이용해 쿼리를 표현할 수 있도록 해주는 객체지향 쿼리 라이브러리
  - 자바 코드이기 때문에 컴파일 시점에 필드 타입과 메서드 체이닝을 검사할 수 있어, 오타나 잘못된 타입 사용을 미리 잡을 수 있음
  - QueryDSL은 동적 쿼리 작성에 최적화되어 있음
- Q클래스: 엔티티를 코드로 쿼리를 작성할 수 있게 해 주는 핵심
  - Q클래스 안에는 엔티티의 필드 타입에 맞춘 경로(Path) 객체들이 들어 있어, 문자열이 아닌 타입 안전한 방식으로 조건을 표현
- JPAQueryFactory: QueryDSL에서 JPQL 쿼리를 자바 코드 형태로 작성하고 실행할 수 있도록 도와주는 핵심 클래스
  
- | 항목 | JPQL | QueryDSL |
  | :--- | :--- | :--- |
  | **쿼리 표현** | 문자열로 작성 | 자바 코드로 작성 (타입 안전) |
  | **파라미터 바인딩** | 수동 바인딩 (`:name`) | 메서드 체인으로 안전하게 바인딩 (`u.name.eq("...")`) |
  | **동적 조건** | 문자열 이어붙이기 / 분기 복잡 | 조건 객체를 조립하듯 추가/제거 용이 |
  | **리팩토링 내성** | 필드명 변경 시 런타임 오류 위험 | Q클래스 기반이라 컴파일 타임에 검증 |
  | **가독성** | 조건 많아질수록 길고 취약 | 도메인 필드가 그대로 드러나 직관적 |
  | **IDE 지원** | 문자열이라 자동완성 / 리네임 한계 | 자동완성, 리네임, 네비게이션 모두 지원 |
  | **성능** | 동일 조건이면 동일 | 동일 (두 방식 모두 최종적으로 SQL로 변환되어 실행) |
