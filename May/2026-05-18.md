### 새로 배운 내용
#### 주제 1: 웹(Web)과 HTTP
- 클라이언트: 원격 서비스에 요청할 수 있는 응용 프로그램이나 서비스
- 서버: 정보나 서비스를 제공하는 컴퓨터 시스템으로 컴퓨터 프로그램 또는 장치
- HTTP: html, css, js, png, jpeg 과 같은 파일이나 텍스트 등 일반적인 텍스트를 뛰어넘는 구조화된 텍스트를 전송하기 위해 사용되는 통신 규약
- HTTP Message: 클라이언트와 서버 간에 파일 등을 주고 받는 통신의 기본 단위
- HTTP Request Method: 웹 서버에게 어떤 작업을 수행하길 원하는 지 알리는 방법을 정의하는 명령 규칙
- HTTP Status Code: 웹 통신 규약에서 요청의 처리 상태를 나타내는 코드
- URL: 리소스의 위치와 종류를 나타내는 주소
  - QueryString: 클라이언트에서 웹 페이지에 대한 추가 정보를 서버에 전달하기 위해 사용되는 문자열
  - Pathvariable: 클라이언트에서 특정 리소스(특정 게시글 조회)에 접근하기 위한 경로 변수

#### 주제 2: RESTful API와 스프링 프레임워크
- REST: 자원을 이름으로 식별하고, 해당 자원의 상태(정보)를 구조화된 형식으로 표현하여, 서버와 클라이언트 간에 정보를 교환하는 방식
- REST API: REST 아키텍처 스타일을 따르는 응용 프로그램 인터페이스
  - 사용이유: 개발자 간의 일관된 통신 규칙을 마련해 업무 효율을 높이고, 단순한 URL 구조를 통해 요청의 목적을 쉽게 이해할 수 있게 하기 위함
- 스프링(Spring) 프레임워크: 자바 애플리케이션에서 객체 생성과 의존성 관리를 자동화해 구조를 단순하고 유연하게 만드는 프레임워크
- IoC: 객체의 생성과 의존성 관리를 개발자가 아니라 외부 컨테이너가 제어하도록 만드는 설계 원칙
    - 객체 생성과 의존성 관리를 컨테이너에 맡김으로써, 코드의 결합도를 낮추고 구조의 유연성과 테스트 용이성을 높이기 위해서
- DI: 객체가 직접 의존 객체를 생성하지 않고, 외부에서 필요한 의존성을 주입받도록 하는 설계 방식
    - 객체 간 결합도를 낮춰 변경에 강한 구조를 만들고, 테스트와 확장이 쉬운 코드를 유지하기 위해서
- AOP: 핵심 비즈니스 로직과 공통 관심사를 분리해, 공통 기능을 코드 수정 없이 일관되게 적용하도록 하는 프로그래밍 방식
  - 공통 기능을 한곳에 모아 코드 중복을 줄이고, 비즈니스 로직을 건드리지 않고도 기능 변경과 확장이 가능하도록 만들기 위해서
- Bean: Spring IoC 컨테이너가 생성하고 관리하는 재사용 가능한 Java 객체
    - 객체를 컨테이너가 관리하도록 표준화해, 의존성 관리·생명주기·구성 변경을 일관되게 처리하고 애플리케이션의 확장성과 안정성을 높이기 위해서
