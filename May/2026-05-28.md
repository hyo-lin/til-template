### 새로 배운 내용
#### 주제 1: 서버 캐시
- Server Cache : 웹 서버가 데이터를 빠르게 제공하기 위해 자주 사용되는 정보를 임시로 저장하는 장소
    - 동작방식: 사용자의 요청에 대해 서버가 이미 처리한 결과를 저장해두고, 동일한 요청이 들어올 때 다시 계산하지 않고 저장된 결과를 바로 제공하여 처리 속도를 빠르게 하고 서버의 부하를 줄이는 방식으로 동작
  
  | 구분 | 로컬 캐시 (Local Cache) | 글로벌 캐시 (Global Cache) |
  | :--- | :--- | :--- |
  | **정의** | 각 서버 인스턴스에 독립적으로 존재하며, 서버의 리소스를 사용하여 데이터를 캐싱합니다. | 여러 서버 인스턴스 간에 공유되며, 네트워크를 통해 접근 가능한 별도의 캐시 서버(Redis, Memcached 등)에서 데이터를 관리합니다. |
  | **장점** | - 데이터 접근 속도가 매우 빠름<br>- 추가적인 네트워크 지연(Latency) 없음 | - 데이터의 일관성과 공유가 용이<br>- 여러 서버 인스턴스가 동일한 캐시 데이터에 접근 가능 |
  | **단점** | - 스케일 아웃(Scale-out) 시 데이터 일관성 유지 어려움<br>- 각 서버 인스턴스의 캐시가 독립적으로 작동하여 데이터 중복 발생 | - 네트워크 통신이 필요하므로 지연 가능성 존재<br>- 로컬 캐시에 비해 접근 속도가 상대적으로 느릴 수 있음 |
  | **예시 데이터** | - 세션 정보 (단일 서버 환경)<br>- 임시 계산 결과 및 인메모리 일회성 데이터 | - 세션 정보 (멀티 서버 분산 환경)<br>- 사용자 프로필 및 권한 정보<br>- 공유 설정, 상품 정보 및 가격 등 공통 데이터 |
- 로컬 캐시 저장 위치
    - 보통 해당 서버의 RAM 내에 저장되며, 그 서버에서만 접근 가능합니다.
- 글로벌 캐시 저장 위치
    - 종종 외부 캐시 서버나 클라우드 기반의 캐시 서비스에 저장되어, 여러 서버나 애플리케이션에서 공유하여 사용할 수 있습니다.

#### 주제 2: NoSQL
- NoSQL : Not only SQL, SQL만을 사용하지 않는 여러 유형의 데이터베이스
  - 데이터의 다양성, 대규모 데이터 처리, 수평 확장 및 유연한 설계 요구에 대한 필요성이 점점 증가하고 있기 때문
- 키-값 저장소(Key-Value Stores)
  - 각 키에 하나의 값이 매핑되는 가장 단순한 형태의 데이터 저장 방식
- 문서 지향 데이터베이스(Document Oriented Databases)
  - JSON, XML과 같은 문서 형식을 사용하여 데이터를 저장합니다.
- 컬럼 기반 데이터베이스(Column-based Databases)
  - 컬럼 단위로 데이터를 저장하고 관리하여, 대량의 데이터를 빠르게 조회하고 분석할 수 있습니다.
- 그래프 데이터베이스(Graph Databases)
  - 데이터를 노드와 엣지로 표현하여, 객체 간의 관계를 중심으로 데이터를 저장하고 조회합니다.

- Eventual Consistency: 일정 시간이 지나면 데이터 일관성이 보장되는 Eventual Consistency 모델
  - 개발자는 데이터 무결성을 직접 관리해야 할 필요가 있으며, 이를 위해 낙관적 동시성 제어(OCC) 같은 기법을 사용
  - OCC: 낙관적 동시성 제어(OCC)는 데이터베이스 시스템에서 동시에 여러 트랜잭션이 데이터를 조작할 때 충돌을 관리하는 방식
  - 트랜잭션을 시작할 때 충돌 가능성을 점검하지 않고, 트랜잭션이 커밋되는 시점에서만 데이터 충돌을 검사
  - 충돌이 감지되면 트랜잭션을 롤백
- NoSQL은 관계형 데이터베이스(RDBMS)와 달리 스키마리스(Schemaless) 구조를 사용하여 유연성과 확장성을 제공
  - 트리 구조 데이터
- Transaction 미지원
- BASE 모델
  - NoSQL은 ACID(Atomicity, Consistency, Isolation, Durability) 트랜잭션 모델을 완전히 버리고,
    BASE(Basically Available, Soft state, Eventual consistency) 모델을 채택
- CAP 이론 (CAP Theory)
  - CAP 이론은 일관성(Consistency), 가용성(Availability), 그리고 네트워크 분할 허용 오차(Partition Tolerance) 중 두 가지만을 만족할 수 있음을 설명합니다.

#### 주제 3: 데이터베이스의 확장
- 데이터베이스를 물리적 또는 논리적으로 분산시키는 기술
- Vertical Partitioning (수직 파티셔닝)
  - 테이블을 열(column) 기준으로 분리하여 자주 접근하는 데이터와 그렇지 않은 데이터를 나눈다.
- Horizontal Partitioning (수평 파티셔닝 또는 샤딩)
  - 데이터를 행(row) 단위로 나누어 여러 테이블 또는 여러 DB에 분산 저장하는 방식입니다.
  - Range-based Sharding: 특정 기준(예: ID 범위, 날짜 범위)에 따라 데이터를 분할
  - Hash-based Sharding (해시 기반 샤딩): 해시 함수를 사용하여 데이터를 일정한 방식으로 샤드에 분배합니다.
  - Composite Sharding (복합 샤딩): 범위 기반과 해시 기반 샤딩을 혼합하여 사용합니다.
- Replication (복제): 나의 데이터베이스에 저장된 데이터를 여러 노드로 복사하여 유지하는 기술
  - Primary/Master (주 노드), Replica/Slave (복제 노드)
